# ZYNORA

Статический frontend на HTML/CSS/Vanilla JS с backend на Node.js и Express, PostgreSQL через Prisma, ручной оплатой MBank QR и Telegram-уведомлениями.

## Возможности

- Каталог с поиском, фильтрами по цене, категории и бренду, сортировкой, карточками товара и рекомендациями.
- Пагинация, сравнение до четырёх устройств и список недавно просмотренных товаров.
- Корзина в браузере, проверка цены и остатков на backend и резерв товара в транзакции PostgreSQL.
- Оформление заказа гостем или авторизованным покупателем, серверный пересчёт суммы, промокоды и персональная ссылка отслеживания.
- Статическая оплата по QR-коду MBank. Оплата подтверждается менеджером вручную; платёжных API нет.
- Telegram-уведомление после создания заказа. Недоступность Telegram не отменяет заказ; попытка и ошибка сохраняются в заказе и логах сервера.
- Вход покупателей, история заказов, избранное и отзывы только для заказанных и подтверждённых товаров.
- `/admin`: статистика, заказы и статусы, управление ценами и остатками, история склада, загрузка фото, промокоды, модерация отзывов, CSV и печатная накладная.
- Rate limiting, серверная валидация Zod, сессии в PostgreSQL, bcrypt-хеш пароля и защищённые маршруты администратора.

## Требования

- Node.js 20 или новее.
- PostgreSQL 16 или новее. Для локального запуска можно использовать Docker Compose.

## Архитектура

- `server.js` — HTTP entry point, versioned REST API, session store, security middleware, health check и Telegram webhook/polling.
- `routes/` — API endpoints по модулям; `services/` — логика заказов, склада, Telegram и storage.
- `validators/` — входные схемы Zod; `middlewares/` — проверка сессии и роли.
- `prisma/schema.prisma`, `prisma/migrations/` — модели и последовательные миграции PostgreSQL.
- `html/`, `css/`, `scripts/` — адаптивный storefront, страницы кабинета и admin dashboard.
- `Dockerfile`, `docker-compose.yml`, `docker-compose.prod.yml`, `nginx.conf` — локальная база и заготовка production окружения.

## Первый запуск

1. Установите зависимости: `npm install`.
2. Скопируйте `.env.example` в `.env`, сохраните заданные Telegram значения и заполните `DATABASE_URL`; задайте `SESSION_SECRET` случайным значением (например, `openssl rand -hex 32`).
3. Запустите базу: `docker compose up -d db`.
4. Проверьте `DATABASE_URL` в `.env`. Для Compose по умолчанию: `postgresql://zynora:zynora_dev@localhost:5432/zynora?schema=public`.
5. Создайте схему по включённым миграциям: `npx prisma migrate deploy`.
6. Заполните первоначальные категории, товары и администратора: `npm run db:seed`.
7. Запустите приложение: `npm start` (или `npm run dev` для перезапуска при изменении файлов).
8. Откройте `http://localhost:3000`.

## Доступ с других устройств в той же Wi-Fi сети

Сервер слушает `0.0.0.0:3000`, а PostgreSQL опубликован только на локальном компьютере. Запустите сайт на Mac командой `npm start`, затем узнайте локальный Wi-Fi IP-адрес:

```bash
ipconfig getifaddr en0
```

Откройте на другом устройстве в той же сети `http://<IP-адрес-Mac>:3000` (например, `http://192.168.1.25:3000`). Mac должен оставаться включённым, а сервер — запущенным. Если сайт не открывается, разрешите Node.js принимать входящие подключения в macOS Firewall и убедитесь, что Wi-Fi роутер не изолирует подключённые устройства (Guest Wi-Fi / AP isolation).

Это HTTP-соединение для тестирования в доверенной локальной сети; оно не шифрует пароли и сессии. Не используйте его в публичной сети или для передачи чувствительных данных. Для доступа через интернет нужны HTTPS, firewall и отдельная production-настройка.

После изменения Prisma schema применяйте `npx prisma migrate dev --name <название>` и коммитьте созданную миграцию.

Для существующей базы предварительно сделайте резервную копию и применяйте миграции командой `npx prisma migrate deploy`. Не используйте `prisma migrate reset` и не удаляйте Docker volume, если нужно сохранить данные.

## Резервная копия базы

Создать дамп локального Compose PostgreSQL: `docker compose exec -T db pg_dump -U zynora -d zynora > backup.sql`.

Восстановить дамп в уже созданную пустую базу: `cat backup.sql | docker compose exec -T db psql -U zynora -d zynora`. Храните копии отдельно от репозитория и проверьте восстановление до production обновлений.

## Цены и остатки

В исходных страницах ZYNORA цены MacBook были помечены «уточняется». Поэтому в seed цены остаются пустыми, остаток — `0`: приложение не выдумывает коммерческие данные и блокирует покупку до настройки.

Войдите в `/admin` и задайте настоящие цены и остатки для каждой модели во вкладке «Товары и остатки». Можно добавлять новые товары в админ-панели. Заказ резервирует товар отдельно от физического остатка. После подтверждения оплаты остаток списывается, а при отмене неоплаченного заказа резерв освобождается. Фото товаров загружаются прямо в админ-панели (JPG, PNG или WebP до 5 МБ).

## Администратор

1. Задайте `ADMIN_EMAIL` в `.env`.
2. Создайте bcrypt-хеш: `npm run admin:hash`. Вставьте напечатанный хеш в `ADMIN_PASSWORD_HASH`.
3. Выполните `npm run db:seed` — он создаст или обновит пользователя администратора.
4. Войдите на `/admin` с указанным email и исходным паролем. Хранится только хеш.

Покупатели могут создавать обычные аккаунты на странице «Аккаунт». Они не получают административных прав.

## Telegram

Укажите `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` в `.env`. Для локальной работы бот автоматически использует long polling: пока запущен `npm run dev`, сообщения и кнопки заказов обрабатываются без публичного URL. Укажите числовой `TELEGRAM_ADMIN_USER_ID`; если он пустой, используется `TELEGRAM_CHAT_ID`.

Для production можно настроить webhook на `<PUBLIC_URL>/api/v1/telegram/webhook` с `TELEGRAM_WEBHOOK_SECRET` в поле `secret_token`. Когда webhook уже установлен в Telegram, сервер отключает long polling. Команда `/start` покажет Telegram ID, команда `/orders` выведет последние заказы. Кнопки меняют статус в PostgreSQL. При подтверждении оплаты система проверяет и уменьшает остаток атомарно; отмена неоплаченного заказа освобождает резерв.

Токен хранится только в `.env`; не помещайте его в HTML, JavaScript, Git или скриншоты. Если токен уже попадал в переписку или репозиторий, перевыпустите его через BotFather.

## QR-код MBank

В проекте уже есть изображение `image/mbank-qr.jpg`. Страница заказа использует путь из `MBANK_QR_IMAGE_PATH` (сейчас `/image/mbank-qr.jpg`). Для замены можно положить настоящее изображение в `public/images/mbank-qr.png` и указать `MBANK_QR_IMAGE_PATH=/public/images/mbank-qr.png`. Это обычная статическая картинка: backend не проводит платежи и не определяет факт оплаты. Покупатель сообщает о переводе кнопкой «Я оплатил», а администратор вручную проверяет поступление денег и подтверждает оплату в панели или Telegram. Только после подтверждения списывается складской остаток.

## Проверка сценария

1. Запустите PostgreSQL, миграции, seed и сервер.
2. Задайте в `/admin` ненулевые цены и остатки.
3. Добавьте товар в корзину, перейдите к оформлению и заполните имя, телефон, город и адрес.
4. После сохранения заказа откроется персональная страница с номером, точной суммой, QR-кодом и историей статусов. Заказ появится в Telegram, если бот настроен.
5. Подтвердите перевод вручную в MBank, затем установите `PAID` в панели или через Telegram-кнопку. Отменённый заказ вернёт зарезервированные единицы на склад.
6. Отзыв становится доступен после статуса `PAID` и должен быть одобрен в админке.

Основные маршруты доступны с версией `/api/v1`; `/api` оставлен для обратной совместимости. Health-check: `/api/v1/health`. Sitemap и robots: `/sitemap.xml`, `/robots.txt`; задайте публичный домен через `PUBLIC_URL`.

Для production запуска сначала соберите приложение: `docker compose -f docker-compose.prod.yml build app`. Затем запустите миграции: `docker compose -f docker-compose.prod.yml run --rm app npx prisma migrate deploy`, после чего `docker compose -f docker-compose.prod.yml up -d`. Задайте в `.env` `POSTGRES_PASSWORD`, `DATABASE_URL` (например, `postgresql://zynora:<url-encoded-password>@db:5432/zynora?schema=public`), сильный `SESSION_SECRET` (не менее 32 символов), `ADMIN_PASSWORD_HASH`, а также Telegram и QR настройки. Nginx слушает порт 80; HTTPS настройте на внешнем reverse proxy и передавайте `X-Forwarded-Proto`. Установите `TRUST_PROXY_HOPS` по числу proxy перед Node.js (обычно `2` для внешнего proxy + Nginx). PostgreSQL и загруженные изображения хранятся в отдельных Docker volumes.

Запуск автоматических проверок: `npm test`. Перед публикацией настройте домен и HTTPS, резервное копирование PostgreSQL и мониторинг.
